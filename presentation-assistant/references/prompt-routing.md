# 大白话需求的提示词路由

## 工作原则

同事说的是业务语言，不是提示词。先理解“要完成什么、手上有什么、谁要用、有什么不能错”，再选择模板。提示词应补全任务边界，不能替同事编造事实。

## 四步路由

1. **识别主任务**：优先看最终成果，而非单个关键词。例如“把巡检照片做成整改表”属于现场记录，不是单纯图片识别；“根据合同做催缴函”主任务是函件草拟，合同只作事实来源。
2. **识别资料角色**：附件是内容来源、需沿用的模板、待修改原件、视觉参考，还是证据。角色不清才问。
3. **识别风险**：合同、金额、付款、对账、外发通知、个人信息、现场安全需增加核对与待确认约束。
4. **选择模板并编译**：从 `prompt-library.md` 选一个主模板。将使用者原话、已上传资料、明确要求和事实边界填入；只为会改变产出的问题追问一两项。

## 输出策略

- 能直接完成：简短复述理解，内部使用提示词并继续做。
- 用户要求提示词：展示“可复制提示词”，包含任务、资料、约束、输出和核对要求；保留未知字段为“待确认”，不虚构。
- 需要外部发送、合同判断、财务结论或安全结论：先给可审核草稿、差异/待确认清单，再由业务负责人决定。

## 不确定时

- 先选更保守的“整理/草拟/待确认”路线；不要因不确定而擅自改合同、发送信息或下财务结论。
- 一个请求可能触发两个动作时，明确主交付和附加交付。例如“整理费用并写一条催缴微信”：先做核对清单，再草拟微信。
- 关键词路由仅作提示；附件内容、上下文和使用者纠正优先。
