# 将真实反馈转为可复用案例

## 收录条件

仅收录使用者确认有价值、且已完成脱敏的案例。每条案例至少包含：

1. 任务目的和受众（通用描述）。
2. 改前问题和为何影响阅读/决策。
3. 实际改动：保留、删减、合并、重组、换页型或微调。
4. 可观察结果：例如“领导能快速判断选项”“表格重点更易找到”；不能写未经验证的效果。
5. 适用边界：什么场景可复用，什么场景不适用。

## 禁止收录

- 公司、项目、商户、客户、个人姓名、联系方式、合同、金额、原始截图或其他可识别信息。
- 未授权模板、外部图片、完整页面复刻或版权不明的资料。
- 只因单个领导偏好而得出的普遍规则。

## 加入流程

1. 使用者先确认当前交付的改动确实解决了问题。
2. 把经验改写成上述五项的匿名案例，不保存原稿。
3. 对类似新任务先以“候选案例”方式引用；再次验证后才上升为通用规则。
4. 只在用户明确要求且具备技能编辑权限时更新案例库；每次更新后用相应的虚构/脱敏请求复测。
