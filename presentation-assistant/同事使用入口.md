# PPT 助手：同事直接使用入口

上传你已有的资料、图片或 PPT 后，直接复制下面任一句，把方括号内容换成自己的即可。不需要先选择模板、页型或工具；助手会说明它选用的成稿模式、模板角色和预检范围。

## 万能入口：直接说大白话

```text
我想处理【直接说你的事情】，资料在【上传的文件/图片/聊天记录】里。请先判断该怎么做；如果我说得不够清楚，只问最影响结果的一两个问题。请把我的话自动整理成合适的执行提示词并直接开始；涉及合同、金额、对外发送或安全时，先给我可核对的草稿和待确认项。
```

## 1. 直接制作 PPT

```text
请做一份【用途】PPT，主题是【主题】，给【谁看】使用。现有资料是【文件/文字/图片】；重点讲清【三件事】；约【页数】页；请直接出可编辑 PPT。
```

## 2. 先看结构，再做成稿

```text
请先为【主题】做一份给【谁看】的 PPT 结构，不要先生成文件。目标是【目的】，我已有【资料】。请列出逐页标题、每页核心信息、需要我确认的内容；我确认结构后再出成稿。
```

## 3. 做领导/决策汇报

```text
请把这些资料整理成管理层决策稿：主题【主题】，需要领导决定【事项】。请突出选项、依据、影响、待确认事项和下一步，约【页数】页。
```

## 4. 做执行或复盘稿

```text
请做执行落地稿：主题【主题】，面向【执行团队/合作方】。请重点呈现目标、排期、分工、依赖、风险和待确认项。资料在【文件/文字】中，约【页数】页。
```

## 5. 做宣传/招商/合作提案

```text
请做对外沟通稿：主题【主题】，对象是【客户/合作方/公众】。请突出受众价值、核心卖点、参与方式和行动引导；只使用我提供或可核验的素材，不写没有依据的承诺。约【页数】页。
```

## 6. 修改或检查已有 PPT

```text
请以我上传的 PPT 为基础，修改【页码或位置】的【文字/表格/版式/图片】；未提到的页面尽量不动。完成后请给出新文件，并做一次静态预检，说明已检查和未检查的内容。
```

### 先诊断，不直接改

```text
请先诊断我上传的 PPT，不要直接修改。请按页指出信息密度、结构、跨页重复、可读性和待确认风险；区分“必须先改 / 建议优化 / 可保留”，并说明哪些结论还需要在 WPS 或 PowerPoint 里确认。
```

### 审美诊断与取舍

```text
请先做我上传 PPT 的审美诊断，不要直接改。请先判断每页是否服务于汇报目标，再从信息层级、留白、版式节奏和表达方式分析；按“必须先改 / 建议优化 / 可保留”列出页码和具体动作（保留、删减、合并、重组、换页型或微调）。没有真实页面渲染的部分请标为“需要目视确认”。
```

### 做视觉升级，但保留内容事实

```text
请对我上传的 PPT 做视觉升级，保留所有已确认事实和未要求改动的页面。先确定适合【受众和用途】的视觉方向，再优化标题层级、留白、版式节奏、图表/关系表达和图片裁切；不要为了好看增加无关装饰。完成后请说明实际渲染检查过哪些页面、改了哪些高影响问题。
```

### 用案例帮我判断该怎么改

```text
我觉得这份 PPT 的【页面/问题】不够好看或不好讲。请结合通用的改前—改后案例，先判断它是该保留、删减、合并、重组、换页型还是微调；说明理由和优先级。不要照抄其他项目的内容、品牌或图片，也不要直接改稿，等我确认后再改。
```

## 7. 只做一键预检

把 `.pptx` 直接拖到同目录的 `一键预检.cmd` 上即可。它不会修改原文件，会在同一位置生成 `文件名_preflight-report.json`。报告中的“通过”仅代表静态预检通过；正式发送前仍建议在 WPS 或 PowerPoint 打开看一遍。

## 小提示

- 没有资料也可以先说想法；助手会把不确定内容标为“待确认”，不把建议写成事实。
- 要沿用某份模板，请直接上传并说“按这个模板做”。
- 要改变结果，直接说“第 3 页改成时间轴”“风格更简洁”“不要先出稿，先给结构”即可。
